## Reproduction and root cause
- Historical claim: requested word-mode/animated captions silently degrade to coarse static anchors and `declareJobDegraded` is never called, so `result.degraded` stays empty.
- Current source: the full ASS document is the only renderer that can express word modes, animation, precise placement, blur, rounded boxes and line wrapping. When it cannot be built, both assemblers fall back to `subtitles=…:force_style=`:
  - `generators/video.ts` `if (!wired)` branch (fallback `force_style` burn).
  - `generators/broll-assemble.ts` `if (!generatedSubtitleAssPath)` fallback.
  Each only pushed a line to `output_lines`; neither called `declareJobDegraded`. `contracts/subtitle-style.ts` already exported `requiresAssDocument` — documented as existing "so the legacy `force_style` fallback knows it is lossy" — with **no callers anywhere**. So a render shipping without the requested captions reported a clean `done`.
- Expected per AGENTS.md §8: a run may not report success while dropping requested output; the loss must be machine-readable on `result.degraded` (the Jobs UI key), not only a log line.
- RED evidence: a full behavioural render needs ffmpeg and real media, so the reproducible RED here is the wiring guard. Temporarily removing the two new declarations (files restored byte-identically afterward, sha256 `4bb9007a…`, `5292da47…`) made `both assemblers wire the fallback into declareJobDegraded` fail: exit **1**, tests 9, pass 8, fail 1. That is the exact condition H-13 describes (no declared degradation).

## Change and proof

It is the human-readable counterpart to `requiresAssDocument`, which is unchanged.
