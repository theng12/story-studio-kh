## Reproduction and root cause
- **NEW-07 (owner-reported, urgent).** The Jobs history rows showed `Model: deepseek-v4.1-flash`,
  `gpt-5.6-luna`, `mimo-v2.5-free` with no provider, though the owner used Token Harbour, Experimental
  Labs and OpenRouter. Trace: gateway-kh publishes `provider_name` per catalogue model and
  `genstudio-client.ts` already parses it for every modality; but the frontend's
  `GenStudioDisplayCatalogEntry` had no provider field, `buildGenStudioModelLabelEntries` built only
  id→name, and `jobModelDisplay()` returned `genStudioModels.displayName(model)`. So the datum reached
  the app and was discarded at display time (AGENTS.md §2).
- **NEW-05.** The key-test probe lists `GET /v1/content/account` expecting 200. gateway-kh's
  `/v1/content/*` routes are a deliberate stub that raises `503 CONTENT_STORE_NOT_CONNECTED` while no
  Content Store is linked (verified in `gateway/api.py` and against the running gateway). The probe
  reported that as `returned HTTP 503. Check the API URL and key.` — blaming a working key and URL
  (AGENTS.md §6).
- **NEW-06.** `DEFAULT_GENSTUDIO_URL` was `http://127.0.0.1:8000`; the owner moved gateway-kh to
  `0.0.0.0:8787` on 2026-09-21 (verified: `/health` 200 with 1,687 models, `/v1/models` 401 without a
  key, reaching `100.126.154.54:8787`). A fresh install could not reach it.
- **RED.** NEW-05 was written against the fixed source and fails at the old behaviour by construction
  (`valid:false`, message blames the key). NEW-06 is pinned by the four test files that fetch through
  the default — they fail if the constant reverts. NEW-07's `buildGenStudioModelProviderEntries` is a
  new pure function with a direct test (published → mapped; unpublished → absent).
