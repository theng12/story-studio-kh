## Reproduction and root cause
All five are the same defect shape AGENTS.md §6 names — "I could not work out the answer" rendering as "the answer is none" — and four of them also left the customer with no recovery action.

- **E-08.** `scanAssets()` clears `scannedAssets`/`scenes` and, on rejection, only raised a toast. Step 1's entire findings panel is gated on `scannedAssets`, so a failed scan rendered a blank step with no visible reason and no control to try again (the only other scan trigger lived inside a warning card that itself needs a successful scan).
- **E-07.** `loadTransitionsCatalog()` swallowed every rejection (`catch { /* non-fatal */ }`). The picker's empty branch was `v-if="!transitionsCatalog.length"` reading "Loading transitions…", so a failed read was indistinguishable from a slow one and stayed on screen forever.
- **E-09.** `subtitlesStatus` initialises to `null` and `loadSubtitlesStatus()` kept only successes. Step 5's banner `v-if="!burnView.burning"` therefore announced "No subtitle file for this episode yet" while the request was still in flight, and permanently after a failure.
- **E-04.** `loadStatus()` on the Subtitles page toasts on rejection and leaves `status` null; the readiness block's first branch is `v-if="!status?.has_chapter_audio"`, so a failed read told the customer there was no chapter audio for an episode the app never managed to inspect.
- **E-05.** `AudioChapterSelector.refresh()`'s `catch` set `sections = []`; the template's `v-else-if="!sections.length"` then said "No sections found. Generate the script first, then this selector will list each chapter to target individually."

- **RED evidence.** Every new assertion names an identifier or branch that does not exist at `HEAD`. `for f in <the four files>; git show HEAD:$f | grep -c <id>` returned **0** for all of `scanError`, `transitionsCatalogError`, `transitionsCatalogLoading`, `subtitlesStatusLoading`, `subtitlesStatusError`, `statusError`, `loadError`, and for the `@click="refresh"`/`@click="loadStatus"` retry sites. The behavioural cases (`scanError` retained on failure and cleared on success; a superseded episode's late failure not labelling the current episode) exercise `useVideoAssemblyIo.scanAssets()` directly, which had no error state to assert against before this packet.
- **Limitation on RED:** the pages themselves were not restored-and-rerun byte-identically for this packet the way DS-09b did; RED rests on the base-commit absence check above plus the behavioural cases. Stated as a limitation rather than claimed as a restored-file reproduction.

## Change and proof
- **E-08:** `useVideoAssemblyIo` gained `scanError` (cleared at each scan start, set from `e.data.detail || e.message` in the catch, returned to the page). `video-assembly.vue` destructures it and renders an `role="alert"` banner in Step 1, where the findings panel would be, with a **Retry asset check** button. `scannedAssets`/`scenes` are still cleared on failure, so a last-valid list can never be submitted — and the render payload carries no scene list at all (the backend re-scans), which `useVideoAssemblyIo.test.ts` already pins.
- **E-07:** `transitionsCatalogLoading` (starts `true`) and `transitionsCatalogError` distinguish in-flight, failed and genuinely-empty; the catch clears the list and retains the detail, and `finally` clears loading on both paths so nothing can hang. The failure branch offers **Retry**.
- **E-09:** `subtitlesStatusLoading`/`subtitlesStatusError` are tracked; the "No subtitle file…" claim is now `v-else-if="episodeId && !burnView.burning"` behind a loading branch and a failure branch with **Retry**. A failed read leaves `subtitlesStatus` null (unknown), never an implied empty. The episode-change watcher clears the previous episode's error and re-arms loading, so one episode's failure cannot stand while another is on screen.
- **E-04:** `statusError` on `subtitles.vue`; the readiness block now reads loading → failed (with **Retry**) → missing audio → not-assembled → coverage.
- **E-05:** `loadError` on `AudioChapterSelector.vue`; the list area reads no-episode → scanning → failed (with **Retry**) → empty-script.
