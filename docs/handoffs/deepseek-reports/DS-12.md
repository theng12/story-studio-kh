## The defects, as reported in round 4 (unchanged evidence)

### F-15a — Scene Plan: the "Avoided imagery" control was unreachable at 1440×900
- **Element:** `label.form-group` inside `div.scene-creative-controls`, within `div.scene-setting-card.scene-creative-card`.
- **Geometry:** rect `1313..1533` at a 1440px viewport — **93px past the right edge**, and 156px past its own card
  (`838..1377`). Its sibling `input.input` sat at the same right edge, so the control and its field were both off-screen.
- **Why unreachable, not merely wide:** the third grid column started at ~1313 with 220px of content; no ancestor
  scrolls horizontally; the nearest clipping ancestor is `main.main-content { overflow-x: hidden }`.
- **Not caused by the X-06 work:** hiding the new `.guidance-reusable` field in the live DOM left the rect identical
  (`1533` → `1533`).

### F-15b — Scene Review: the command bar ran 13px off-screen at 1440×900
- **Element:** `div.region.generate-region` (primary CTA plus status) inside `div.top-action-bar` →
  `div.review-command-bar` → `div.review-workspace` → `main.main-content`.
- **Geometry:** rect `1150..1453` — **13px past the viewport**, clipped. Also carried `span.popover-root`,
  `button.btn.btn-primary.btn-primary-cta` ("Finish 0 missing images · may use credits") and
  `p.generate-status` ("Pick an episode first").

## The fixes (smallest complete change, page-scoped CSS only)

### F-15a
```css
.scene-creative-controls {
  /* demanded 680px (three 220px minimums) inside a ~509px card, so the third control
     was laid out past the card and past the viewport and clipped away */
  grid-template-columns: 1fr 1fr;
  ...
}
.scene-creative-controls > * { min-width: 0; }
.scene-creative-controls > :first-child { grid-column: 1 / -1; }
```
The intensity picker spans the row on purpose: its four labels need ~360px, which no third of this card provides at
any realistic window width. The redundant copies of those two declarations were removed from the `max-width: 1100px`
block (the `max-width: 680px` single-column rule is unchanged).
- **First attempt (rejected):** shrinking the three tracks to `minmax(0, …)`. It did put the third control back inside
  the card, but it squeezed the four intensity choices to 29px each and ellipsised every label to a single letter —
  see `qa/ds12-f15a-scene-plan-first-attempt-1440x900.png`. The rendered result, not the geometry alone, decided it.

### F-15b
```css
.review-command-bar :deep(.top-action-bar) {
  grid-template-columns: minmax(0, auto) minmax(0, 1fr) minmax(0, auto);
}
.review-command-bar :deep(.preset-region),
.review-command-bar :deep(.episode-region),
.review-command-bar :deep(.generate-region) { min-width: 0; }
.review-command-bar :deep(.generate-region),
.review-command-bar :deep(.generate-status) { min-width: 0; }
```
The `max-width: 1400px` rule (which stacks the CTA on its own row) is untouched; at 1440 the viewport is wide while
the workspace is not, so the tracks now shrink instead of overflowing.

### F-14 — found by the rendered pass, fixed here
- **Symptom:** the Notification center's `position: sticky; bottom: 10px` save bar measured **exactly its natural
  document offset at every scroll position** (`1867`, `1411`, `955`, `500`, `44` for scroll offsets 0/456/912/1367/1823
  on a 2680px page) — i.e. the declaration did nothing and Save was invisible until the very end of the page.
- **Cause:** `.notification-panel { overflow: hidden }` made the panel the bar's **scroll container**; a
  hidden-overflow ancestor never scrolls, so the sticky offset could never be non-zero.
- **Proof:** overriding the panel to `overflow: visible` in the live DOM moved the bar from `top: 1867` to
  `833..898` at scrollTop 0. `overflow: clip` keeps the corner clipping but is not a scroll container.
- **Fix:** `.notification-panel { overflow: clip }`.
- **After:** bar `top` at the five offsets is `833 / 377 / 117 / 117 / 54` — inside the viewport at every one of
  them, and the Save button is the topmost element at 50/75/100% (`elementFromPoint` returns it).

**F-13 — the six named shared utility classes** (`.input-sm`, `.btn-icon`, `.link-btn`, `.checkbox-label`,
`.section-kicker`, `.card-actions`). Source declares them globally in `frontend/assets/css/main.css` (registered in
`nuxt.config.ts`), not in component `<style scoped>` blocks. Verified three ways against the tree built at 1.4.217:
1. The built entry CSS contains all six as **unscoped** rules (`entry.D0tCFUSq.css`).
2. Consumers that declare nothing locally compute exactly the global declaration — `.link-btn` on `scripts.vue`
   (padding `0`, border `none`, color `rgb(240,198,116)`, cursor `pointer`) and `.section-kicker` on `pipeline.vue`
   (block, `uppercase`, 12px/600, `0.06em`, muted, `margin-bottom: 4px`).
3. A probe element appended to `document.body` — **outside `#__nuxt`, the same DOM position every teleported dialog
   occupies** — computes the declared values for all six: `.input-sm` `6px 10px`/13px, `.btn-icon` `inline-flex`/`4px 6px`
   with no border or background, `.link-btn` accent color with no border, `.checkbox-label` flex with `gap: 8px`,
   `.section-kicker` block/uppercase/12px/600/`0.72px`, `.card-actions` flex-wrap with `gap: 8px`.
   Because these are global class selectors with no ancestor and no scope attribute, a teleported consumer cannot
   be excluded, which is the property the row asked to verify.
   A scan for *other* shared-but-scoped-only class names was attempted and abandoned: distinguishing a real class
   token from a string literal or object key in `:class` expressions needs a real template parser, and the noisy
   first pass was not evidence. Recording that rather than a hand-picked list.

## Not done, and why (honest gaps)
- **F-12 — purchase dialogs at 800×500.** Still blocked by the fixture: the Content Store in the disposable library
  reports `Discover 0 / Owned 0 / Installed 0 / Updates 0` and offers only "Retry Content Store" (no GenStudio scope
  or key), so `ContentPurchaseDialog` and `ContentBatchPurchaseDialog` cannot be opened without a real catalogue.
  No purchase was attempted. The What's New dialog remains the one short-viewport specimen (round 4).
- **F-14's 0% and 25% offsets are verified by geometry, not by a fresh screenshot.** In this long-lived harness the
  compositor stopped producing new frames for regions below roughly y=250 (two separate captures returned a
  byte-identical PNG, and `elementsFromPoint` at that depth returns only `<html>` even for laid-out, `visibility:
  visible` elements). The bar's rect is measured inside the viewport at those offsets, and the 50% screenshot shows
  the bar painted with its Save button. This is a harness artifact, not an app finding — but it is why the visual
  claim rests on the 50% frame.
- **No automated regression gate for any of these three.** Every one is layout, and per AGENTS §3 a gate cannot see
  geometry: nothing in `test:backend`, `test:frontend` or `build` would have caught them, and nothing added here
  would catch the next one. The defence is the rendered probe, kept reproducible by this report.
