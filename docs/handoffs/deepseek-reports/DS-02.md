## Reproduction and root cause
- Exact fixture and expected versus actual:
  1. A disposable project gets a `jobs.json` with one persisted `running` job of type `metadata`, `image_prompts` or `research_run`, carrying a durable, unsettled GenStudio chat task (`genstudio_jobs: [{ id: 'chat-<type>-1', operation: 'chat.response', state: 'accepted' }]`) and no cancellation context.
  2. `getJobs(project)` loads it through the real boot path; the load routes it to `reconcileCancellationJob` and sets `local_execution_complete = true` (correct: a durable provider identity must settle).
  3. A read-only provider read (fake `GET /v1/chat/responses/:id`) answers `succeeded`.
  4. `finalizeSettledProviderJob` needs a registered output auditor. `boot/executors.ts:registerCancellationAuditors` registers none for `metadata`, `image_prompts` or `research_run`, so the old branch pushed "…no output auditor is registered. Keeping this job running…" and returned.
  - Expected per AGENTS.md §8: unverifiable output is never success, so the row must fail loudly with an actionable state.
  - Actual: the row stayed `running` forever. The evidence is now settled, so `requiresCancellationReconciliation` is false and no reconcile timer is rescheduled; `retryTerminalJob` refuses anything that is not `error`/`cancelled`; the only control left is Abandon. A stuck, retry-less row holding the duplicate lock.
- RED command, exit, failing assertion; why this is not a setup failure:
  - `node scripts/testing/run-backend-tests.mjs --only job-restart-paid-evidence` → **exit 1**, tests 6, pass 3, fail 3.
  - Failing assertion (verbatim, first of the three): `AssertionError: metadata was left status=running after its provider task settled; … lines=↻ Story Studio restarted — reconciling the existing GenStudio request before allowing any retry. | Provider work settled, but no output auditor is registered. Keeping this job running until output can be verified.`
  - Not a setup failure: the fixture registers the **production** auditor set (`registerAllExecutors({ loadSettings: false })`), and both controls in the same run passed — `scene_plan_run` (which *does* register `auditScenePlanOutput`) reached an honest `error`, and a job with no durable evidence kept the plain `Interrupted by app restart` error with zero provider reads.
- Current-source callers and ownership/completion boundary:
  - `reconcileCancellationJob` (`job-queue.ts:676`) → `reconcilePendingJobCancellation` (`job-cancellation-reconciler.ts:233`) → `finalizeSettledProviderJob` (`job-queue.ts:927`).
  - `getJobCancellationAuditor`/`registerJobCancellationAuditor` (`job-cancellation-auditors.ts`); production registration is `boot/executors.ts:147-219`.
  - `retryTerminalJob` (`job-queue.ts:5280`) refuses non-terminal rows; `classifyProviderJobControl` (`job-control.ts:211`) has no "settled but unverifiable" state and falls through to a disabled "Return later", with force-abandon appended.

## Change and proof
- Minimal change: in `finalizeSettledProviderJob`, the no-auditor branch now fails loudly instead of returning while `running`:
  `status='error'`, an honest message naming the missing completion audit and that Retry re-runs the step, `result.provider_settled='succeeded'`, `repair_required: true`, `finished_at` set, the message appended to `output_lines`, then persist/emit.
  Provider evidence is left untouched. No auditor, timer, retry or duplicate-lock semantics were changed; no new helper, dependency or abstraction.
- Why the root cause is here and not in the type list: the branch is generic. A settled provider task with no way to verify output is a dead end for *any* type that reaches it, not only the three named. Failing loudly closes the class. Adding per-type auditors for `metadata`/`image_prompts`/`research_run` is a larger, separate improvement (recorded below as `NEW-02`), not required to satisfy the contract.
- Safety check that this cannot break a live executor: `finalizeSettledProviderJob` guards on `local_execution_complete === true`. A live executor sets that only at its own completion boundary (`job-queue.ts:3479`), immediately before `completeSuccessfulJob`; while evidence is still unsettled the reconcile timer is the only scheduler, and once evidence is settled `requiresCancellationReconciliation` is false so no timer remains. The branch is therefore reached by recovered/restart rows, not by in-flight generators.
