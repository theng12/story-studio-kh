## Why this shape
- **No second backend field.** The planner has exactly one guidance input (`custom_instructions`, appended to the prompt as `ADDITIONAL INSTRUCTIONS`); it is threaded through ~15 sites in `services/scene-planner.ts` and the scene-plan routes. The reusable box is about *where the text is kept*, not about provider capability, so the two boxes are composed into the one input the backend already accepts — the smallest complete change. When only one box has text the payload is byte-identical to what the page sent before the field existed; when both do, the blocks are labelled in the text so the model and the job log can tell them apart.
- **Preset-only is load-bearing, in both directions (AGENTS.md §5's trap).** `usePresets.excludeKeys` strips on write *and on read*, so `reusable_guidance` must NOT be excluded: excluding it would discard the customer's own text on the way back into the form, and the preset is its only durable home. `custom_instructions` stays excluded (owner decision #9) and the page's snapshot is pinned by a test that reads the page, because the round-trip cases supply their own snapshot and would not notice the field going missing.
- **A preset saved before this field existed must not blank the live text.** `Object.assign` cannot remove a key the preset never stored, and there is no normaliser default, so nothing has to be carried across the apply. Pinned by `X-06: a preset saved before the reusable field existed does not blank the live text`.
- **§4 repair found while implementing.** The episode-only box was labelled "optional" but its text survived an episode change and was sent with the next episode's prompts — the exact AGENTS.md §4 shape. It is now cleared on an episode change, the clear is announced (`episodeGuidanceNotice`, cleared again once the customer types), and the reusable box is deliberately NOT cleared because it is not owned by an episode. The label now reads "this episode only".
