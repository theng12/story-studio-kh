#### [P1] Image-style analysis from reference image (user pain-point #7) — ⚠ discuss
- **Where:** new feature, no existing location
- **Impact:** User wants to upload a reference image and have the app extract style/art format, then feed that into the prompt template for consistent generations. Critical for channel-brand consistency.
- **Proposed fix:** **Needs design session.** Options to compare:
  1. **Local CLIP + captioner** (e.g. BLIP-2 via `@xenova/transformers`) — free, offline, but heavyweight install, limited accuracy for style keywords.
  2. **Vision LLM call** (Claude 4 / GPT-4o vision) — high accuracy, produces a natural-language style sheet, costs per extract, needs a key the user already has.
  3. **Provider-native tagger** (fal.ai has image-to-tags endpoints) — fast, cheap, lower fidelity than vision LLM.
  - Recommend option 2 first: we already wire Anthropic + OpenAI, a single vision call returns a reusable style sheet, persist it as a preset. Add #1 or #3 later if offline mode matters.
- **Size:** L (once direction is chosen)

#### [P1] Thumbnail text-style preset list too short, no custom field, no font variety
- **Where:** image-prompts.vue thumbnail section
- **Impact:** User's pain-point #8 — only a handful of text styles, no custom, few fonts. User wants: more presets, custom field, more font descriptors, "Surprise me" randomizer.
- **Proposed fix:** Expand the preset list, add a custom-text input with helper copy, add a ComboInput-style font picker with many options, and a 🎲 randomize button next to each value.
- **Size:** M

#### [P2] No explanation of scenes-vs-thumbs split
- **Where:** top of image-prompts.vue
- **Impact:** New users don't know why prompts are split into two pools.
- **Proposed fix:** Lead paragraph explaining the two-pool system.
- **Size:** XS

  - **Option A — LaMa (open-source, local):** `lama-cleaner` is an FFmpeg-ish CLI + Python backend for inpainting. Heavy install, high quality. Suitable for an Electron-packaged native helper.
