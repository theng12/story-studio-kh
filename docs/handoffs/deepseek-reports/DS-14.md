## What the packet found

Three things, in the order they surfaced.

### 1. The coarse pre-filter could hide a whole file
The file loop skipped any source whose text matched none of a list of catalogue-ish words (`gpt-|claude-|…|credit|price|cost|tokens|…|\d{1,2}:\d{1,2}`). Two real shapes contain none of those words:

- `controls.stability` — a `named-control` violation: the word `controls` is not in the list.
- `{ max_reference_images: 3 }` / `max_image_dimension` — a `catalogue-field-literal`: neither field name contains a trigger substring.

So a file whose only catalogue mistake was one of those was never read at all, and the guard still printed "passed". **The pre-filter is now gone.** Measured cost of scanning every file: **0.81 s for 708 files** — the speed it was buying was not worth a silent hole.

### 2. Removing it surfaced a live violation
With every file read, the guard immediately reported a real finding the gate had always hidden:

```
frontend/utils/genstudio-relaxed-queue.ts:55 — a currency amount "$${" appears in a cost string
```

Investigated rather than annotated away: `moneyFromCents()` renders **GenStudio's own published cents figure** from a `RelaxedQueueHint` (`hint.cents / 100`). The rule's premise — "a dollar figure can only have come from a per-token rate hardcoded here" — does not hold, and the file's own doc comment already says so ("Cents become dollars here because dollars are how he says it; the amount itself is GenStudio's"). The honest disposition is one written exception, not a rules rewrite:

```ts
// model-drift-allow: this renders GenStudio's own published cents figure, never a Story-owned rate
```

The exception count went 38 → **39**, and the guard now catches the next one of these instead of hiding it.

### 3. The module-specifier exemption never fired
The rule comment claims "Module specifiers are file paths, not catalogue values", and `MODULE_SPECIFIER_CONTEXT` was written to exempt them. It could never match the ordinary form: `import type { Client } from 'gpt-4o-sdk'` leaves the **opening quote** as the last character before the match, and the pattern ended in `\s*$`. Every quoted specifier was therefore reported as a product identifier. The pattern now allows the quote, so the documented behaviour is the real behaviour. A documented exemption that never fires reads as protection that does not exist.

## Testability change and its proof
The guard was a self-executing script with no exports, so nothing could exercise it on fixtures. It now exports `analyzeModelDriftSource(raw, path)` (pure, per file), `scanForModelDrift({ root, roots })` (the real walk + analyzer), `modelDriftRules`, and `modelDriftScanRoots`; the CLI calls the same function with the repository and the production roots. Nothing was re-implemented for the tests.

- **Behaviour preserved:** the original script (`git show HEAD:…`, placed in-repo so its own `repoRoot` resolves) and the refactored script produce **byte-identical stdout and the same exit code** (`diff` clean).

## Tests (`scripts/release/__tests__/model-drift-guard.test.mjs`, 7 cases)
Fixtures are written to a fresh temp dir — nothing is planted in production source — and scanned by the real `scanForModelDrift`.

1. **Every declared rule fires** on a real violation (and no violation belongs to an undeclared rule) — the rule inventory cannot rot.
2. **The three historical misses are caught by name and file**: the wrapped `optionalCount(payload?.maximum_input_characters) ?? 0`; the bare `payload?.credits ?? 0`; the guarded ternary with a `SCREAMING_CASE` constant.
3. Findings are reported at the right line and carry a teaching message.
4. **Every legitimate control stays silent**: a valid annotation; `min_reference_images ?? 0` (an unpublished minimum is no constraint); `RESOLUTION_FACTOR[settings.resolution] || 1` (a subscript is a key, not a read); `productPublishesControl(model, 'temperature')`; a bare live read; a quoted module specifier; `?? fallbackVariable` (no invented literal).
5. A **malformed justification** (fewer than four words) is a failure, not a blanket suppression.
6. **No pre-filter may hide a file** — the fixtures that killed the gate are kept as the regression test.
7. **Live application code is still clean**: the same analyzer against the real scan roots, in a lane that runs far more often than a release.
